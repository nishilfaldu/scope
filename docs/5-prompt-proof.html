# Scope credential flows

This document traces the credentials used to connect an agent to Scope and to connect a provider account to Scope. It is written from the outside in: what the agent or browser sends, which Convex function runs, which database rows change, and where each secret exists at every point.

## System boundaries

```mermaid
flowchart LR
  Agent[Agent runtime] -->|Scope HTTP API| HTTP[Convex HTTP actions]
  Browser[Operator browser] -->|Convex authenticated functions| Functions[Convex queries and mutations]
  HTTP --> DB[(Convex database)]
  Functions --> DB
  Browser -->|OAuth redirect| Provider[OAuth provider]
  Provider -->|authorization code| HTTP
  HTTP -->|server-side token exchange| Provider
```

The browser never receives an agent connection secret, an OAuth access token, or an OAuth refresh token. The agent receives an agent connection secret through the private claim flow. Provider tokens stay in Convex except for freshly minted provider access tokens issued through the separate slice credential API.

`activateReplacement` performs one Convex transaction:

1. `agentConnectionBySecret` reads the replacement row and verifies the supplied secret hash.
2. If the row is already `active`, it returns success. This makes activation idempotent after a lost response.
3. Otherwise it requires `status === "staged"`.
4. It reads the invite through `agentConnectionInvites.by_agent_connection_id` and requires `approved`, unexpired, and a `replacesAgentConnectionId`.
5. It reads the previous generation and requires it still be `active`.
6. It reads every `slices` row through `slices.by_agentConnectionId` and moves it to the replacement.
7. It reads `sliceRequests` through `sliceRequests.by_agentConnectionId` and moves pending or approved requests to the replacement.
8. It marks the previous generation `revoked` and the replacement `active`.
9. It marks the invite `claimed` and clears `issuedSecretCipher`.

The previous credentials remain usable until step 8 commits. The replacement credentials cannot authenticate ordinary agent operations while their row is `staged`, because `activeAgentConnection` requires `active`.

If activation never happens, `expireInvite` revokes the staged row and clears the encrypted replacement secret. It does not modify the previous active generation, its slices, or its pending requests.

Test behavior

Refactor the test suite in `<insert_scope>` so every test earns its keep: it calls the code the way its users do and asserts a result they observe. Tests exist to catch defects, not to restate the code.

The bar for keeping a test: it would fail if the behavior it covers broke. The quick check - if the test would still pass when every function it imports returned `undefined`, it observes no behavior and cannot fail for a defect. Rewrite the assertion or delete the test.

Shapes that fail the bar:

- Weak or no assertion: no `expect`, or only `toBeDefined`, `toBeTruthy`, `not.toThrow`, `toBeInstanceOf`.
- Mock or absence only: asserts that a mock was called, or only that something is undefined, empty, or not the wrong value.
- Self-referential: the expected value comes from the code under test.
- Constant pin: restates a hand-maintained constant, config default, table row, or prompt string.
- Fixture asserts fixture: asserts on data the test built while the subject never runs inside the test body.

Where real behavior exists underneath, fix the test: call the subject inside the test body with one concrete input and assert the literal output or the observable effect. For an absence, assert the presence on the other input in the same test. For a constant, test the mechanism that reads it instead of restating the value. For a mock, assert the payload it received or the state after the call, not that it was called. When no such assertion exists, delete the test. Prefer no test over a bad test.

Keep tests of relations across rows (a key present in two tables, a parent that exists) and compile-time checks in `*.test-d.ts` files.
